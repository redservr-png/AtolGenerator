# 1С УТ 10.3 и COMConnector

Программа подключается к 1С через внешнее COM-соединение `V83.COMConnector`.
Официальное описание: [Внешнее соединение](https://v8.1c.ru/platforma/vneshnee-soedinenie/).

## Что читает программа

Для реализаций используются номер и дата документа, заказ, контактное лицо,
сумма, договор, подразделение, номер чека ККМ, ФП и дата печати чека. Для
Obsidian-кейсов дополнительно читаются комментарий и доступные фискальные поля
ПКО, РКО и оплаты картой.

Номенклатура загружается, когда нужна обычная или исправительная пара чеков.
Для одиночного чека коррекции ФФД 1.05 табличная часть не формируется, но договор,
подразделение и классификация услуги нужны для определения НДС.

## Подключение

Настройки хранятся в `onec_settings.json` рядом с exe:

- сервер `Srvr`;
- имя базы `Ref`;
- пользователь;
- пароль.

COM работает только в Windows. Разрядность приложения должна совпадать с
доступным COM-компонентом 1С. Если `V83.COMConnector` не зарегистрирован:

```powershell
regsvr32 "C:\Program Files\1cv8\<версия>\bin\comcntr.dll"
```

Команду запускают от имени администратора. Для 32-разрядной платформы путь может
находиться в `Program Files (x86)` и следует использовать x86-сборку программы.

Подробности: [документация 1С EDT](https://its.1c.ru/db/content/edtdoc/src/topics/t000419.html).

## Запись обратно в 1С

Основной путь после сверки XML + журнала АТОЛ — вкладка `Отчёты → Загрузка в 1С`:

1. сопоставить файлы;
2. нажать `Записать в 1С через COM` — программа пишет через `V83.COMConnector`;
3. параллельно сохраняется CSV-резерв в `atol_output/` на случай сбоя COM.

**В реквизит `Комментарий` документа ничего не пишется** — он уходит в обмен с
бухгалтерией. Фискальные данные и текст «Пробит …» записываются в доп. свойства
группы `ЧекиКоррекции/Исправления` (`РегистрСведений.ЗначенияСвойствОбъектов`):

- `КомментарийКорректировки`
- `ДатаПечатиЧека`
- `НомерЧекаККМ`
- `ЧекНомерФП`

Свойства можно писать и в закрытом периоде. Реквизиты чека на документе — только
при открытом периоде и только в режиме `update_fields`.

- `update_fields` — одиночный `sell_correction`: реквизиты чека на документе +
  те же данные в свойства + текст с датой регистрации в `КомментарийКорректировки`;
- `comment_only` — исправительная пара (`sell_refund` + `sell`/`sell_correction`):
  реквизиты документа **не трогаем**; по **два чека** пишем в регистр свойств
  (комментарий с датой каждого чека, ФП/ФД/дата — через `WriteCheckPropertiesBundle`
  для каждой строки пары, комментарии объединяются через `   ///   `).

Кнопка `Сохранить CSV для 1С...` остаётся запасным путём для ручного импорта
обработкой `ИмпортЧекНомерФПИзCSV` (обработку CSV пользователь дорабатывает отдельно).

Контракт CSV: [ТЗ импорта](../ТЗ_доработка_обработки_1С_импорт_чеков.md).

## Режимы записи

- `update_fields` — одиночная коррекция: поля чека на документе + свойства;
- `comment_only` — исправительная пара: исходный ошибочный чек в реквизитах
  остаётся, оба новых чека — только в свойства (по одной записи на чек).

Повторная запись не должна создавать дубли по ФПД (проверка по тексту свойства).
